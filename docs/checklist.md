# Чек-лист Roomly

[Среда и способ проверки](report.md) · [Найденные ошибки](bugs.md) · [Требования](spec.md)

Обновлено после дополнительной проверки 23.11.2026. Подробные данные, шаги и результаты по техникам тест-дизайна — в [сценариях](scenarios.md).

В основной набор добавлены автотесты для C12 (два имени с разметкой), C17 (смена суток с перезагрузкой и без неё) и проверки заголовка из C14 (320/820/821 px). Весь набор с параметрами: **6 passed, 5 xfailed**. Таблица ниже сохраняет результаты исследовательской проверки. У автоматизированных сценариев `FAIL` известного бага соответствует `XFAIL` его теста; BUG-02 и BUG-03 пока проверяются исследовательскими сценариями.

P1 — основной сценарий и правила бронирования. P2 — дополнительные случаи и удобство работы с формой. PASS и FAIL относятся к вариантам, указанным в строке; NOT RUN — к тому, что осталось проверить.

| ID | Приоритет | Что проверено и как отработала форма |
| --- | --- | --- |
| C01 | P1 | **PASS** — Малая на 4, Средняя на 10 и Большая на 20 участников при длительности 30 и 240 минут. Во всех шести случаях в подтверждении были верные комната, дата, время и имя. |
| C02 | P1 | **PASS** — у пустой формы появились семь ошибок. Затем каждое обязательное поле оставляли пустым по отдельности: комнату, дату, начало, окончание, участников, имя и почту. В каждом случае форма показала ошибку у нужного поля и отклонила бронь. |
| C03 | P1 | **PASS** — −1, 0 и 21 участник отклонены, 1 и 20 приняты в пределах вместимости комнаты. Для Малой проверены 4 и 5 участников, для Средней — 10 и 11, для Большой — 20 и 21: на пределе бронь проходит, выше предела — нет. |
| C04 | P1 | **PASS** — вчерашняя дата отклонена, сегодня 23:00–23:30 и завтра 10:00–10:30 приняты. **FAIL** — сегодня 00:00–00:30 тоже принято, хотя встреча уже закончилась. [BUG-02](bugs.md#bug-02) |
| C05 | P1 | **PASS** — интервал 10:00–09:59 отклонён с ошибкой у времени окончания, 10:00–10:30 принят. **FAIL** — 10:00–10:00 тоже принят. [BUG-01](bugs.md#bug-01) |
| C06 | P1 | **PASS** — встречи на 30, 31, 239 и 240 минут приняты. **FAIL** — встречи на 0, 1, 29, 241 и 1439 минут тоже приняты. [BUG-01](bugs.md#bug-01) |
| C07 | P1 | **PASS** — обычный адрес и адрес с `+` приняты. Адреса без `@`, без части до или после `@` и с пробелом внутри отклонены. **FAIL** — приняты `qa@@example.com`, `qa@-example.com`, `qa@example-.com`, `qa@example..com`, `qa<@example.com`. [BUG-03](bugs.md#bug-03) |
| C08 | P1 | **PASS** — для каждой из трёх комнат название, дата в формате ISO, начало, окончание и имя в подтверждении совпали с введёнными. |
| C09 | P1 | **PASS** — при заполнении и отправке формы в сетевом журнале были только запросы ресурсов при загрузке и перезагрузке страницы. Запросов с данными формы не обнаружено. |
| C10 | P1 | **PASS** — после перезагрузки до отправки введённое имя исчезло. При перезагрузке после успешной брони очистились все семь полей и сообщение о результате. Доступные странице cookies, localStorage, sessionStorage и список баз IndexedDB были пусты до и после проверки. |
| C11 | P2 | **PASS** — после смены Большой комнаты на Малую при 20 участниках появилась ошибка вместимости. После исправления числа участников на 4 и повторной отправки ошибка исчезла, появилась бронь Малой комнаты. |
| C12 | P1 | **PASS** — пустое имя, обычные и неразрывные пробелы отклонены. Имена с кириллицей, дефисом и апострофом показаны верно. **FAIL** — `Анна <QA>` теряет часть имени, `<b>Анна Тестова</b>` становится разметкой в подтверждении. [BUG-04](bugs.md#bug-04) |
| C13 | P2 | **Наблюдение** — приняты 1,5 и 3,9 участника; запись `2e0` тоже проходит. Требование к целым числам и формату ввода нужно уточнить. **NOT RUN** — начало в текущую минуту; переход суток проверен отдельно в C17. |
| C14 | P2 | **PASS** — Tab/Shift+Tab проходят все поля в прямом и обратном порядке, Space на кнопке и Enter из поля почты отправляют форму. На 320, 360, 375, 560, 561, 768, 820, 821, 1024 и 1350 px форма заполняется и отправляется. **FAIL** — на 821 px обрезан заголовок. [BUG-06](bugs.md#bug-06) |
| C15 | P1 | **PASS** — все восемь сочетаний прошлой даты, превышения вместимости и неверной почты обработаны по таблице решений. У валидного варианта есть подтверждение, у остальных — ровно нужные ошибки полей. |
| C16 | P1 | **PASS** — шесть попарных сочетаний комнаты, числа участников, длительности, будущей даты и способа отправки. Все пары значений покрыты, подтверждения соответствуют введённым данным. |
| C17 | P1 | **FAIL** — после перехода с 23:59 на 00:01 открытая форма принимает вчерашнюю дату. **PASS** — после перезагрузки она отклоняется. [BUG-05](bugs.md#bug-05) |
| C18 | P1 | **PASS** — при одном UTC-моменте минимальная дата соответствует локальной дате в Москве, UTC и Лос-Анджелесе. |
| C19 | P1 | **PASS** — после успешной брони новая отправка с лишним участником показывает ошибку; после исправления и повторной отправки появляется новое подтверждение. Очистка имени и Enter приводят к ошибке имени. **Наблюдение** — до повторной отправки старое подтверждение остаётся видимым при редактировании полей. |
