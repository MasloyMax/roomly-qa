# Дополнительные сценарии проверки Roomly

Здесь записано, что проверялось на [опубликованной форме](https://rcsi-science.github.io/demo-roomly/), с какими данными и что получилось. Правила формы собраны в [требованиях](spec.md), краткие результаты — в [чек-листе](checklist.md), найденные ошибки — в [баг-репортах](bugs.md).

## Что проверялось

Цель сессии — проверить границы правил бронирования, сочетания ошибок и случаи, которых не было в первом чек-листе: смену суток в открытой вкладке, разные часовые пояса, клавиатуру и ширины около точек перестроения страницы.

Основная проверка прошла 23.11.2026, 20:19:57–20:20:28 МСК; проверка текстовых полей и состояний формы — в 20:21:53–20:22:00 МСК. Браузер — headless Chromium 156.0.8078.4. Опубликованные HTML, JS и CSS совпали с локальными исходниками после приведения переводов строк к LF. Поля заполнялись через браузерные элементы, отправка выполнялась кнопкой или клавиатурой. Учётная запись и подготовка серверных данных для этой формы не нужны.

Базовые условия для таблиц ниже:

- Часы браузера: **15 января 2030 года, 12:00 МСК**, часовой пояс `Europe/Moscow`, локаль `ru-RU`.
- Встреча: **16 января 2030 года, 10:00–10:30**, «Малая», **4 участника**.
- Имя: `Анна Тестова`, почта: `qa@example.com`.
- Размер окна: **1350 × 805**, если в сценарии не указано другое.

В разделах про имя, почту и состояния формы исходное число участников — **2**; остальные базовые данные те же. В каждой строке меняются только указанные значения. После заполнения нажимается «Забронировать». Ожидаемый успех означает подтверждение с верными комнатой, датой, временем и именем, без ошибок полей. Ожидаемый отказ означает, что успешная бронь не появилась, а форма объяснила ошибку.

`PASS` — наблюдение совпало с ожиданием, `FAIL` — подтверждённое расхождение. Вопросы без согласованного правила записаны отдельно.

## Приоритеты

**P1:** вместимость, длительность, дата, сочетания ошибок и корректность подтверждения. Ошибки здесь позволяют подтвердить недопустимую встречу или мешают обычной брони.

**P2:** доступность полей с клавиатуры и отображение на разных экранах. Эти проверки помогают заметить проблемы, которые не видны при обычном заполнении формы на широком экране.

## Как повторить

### Автотесты новых дефектов

Сценарии BUG-04–06 теперь входят в обычный набор pytest. Это отдельный запуск регрессионных проверок; записи предыдущей исследовательской сессии из 124 вариантов и её снимки сохранены.

| Автотест | Варианты | Результат на текущей форме |
| --- | --- | --- |
| `test_name_is_displayed_as_text` в [test_booking.py](../tests/test_booking.py) | `Анна <QA>` и `<b>Анна Тестова</b>` | 2 XFAIL: имя интерпретируется как разметка. Тест допускает буквальное отображение без созданного элемента `qa`/`b` или явную ошибку только поля имени |
| `test_past_date_is_rejected_after_midnight` в [test_booking.py](../tests/test_booking.py) | Открытая форма без перезагрузки; отдельный вариант после перезагрузки | Без перезагрузки XFAIL, контроль после перезагрузки PASS |
| `test_heading_is_not_clipped` в [test_layout.py](../tests/test_layout.py) | 320, 820 и 821 px | 320/820 — PASS; 821 — XFAIL |

В автотесте полуночи часы устанавливаются на 15 января 2030 года, 23:58 до открытия страницы. После загрузки время останавливается на 23:59, продвигается на две минуты через `fast_forward`, затем ход часов возобновляется. Таймеры страницы при этом срабатывают. Исследовательский снимок выше получен при прямой смене фиксированного времени; его условия не менялись.

Проверка вёрстки ждёт шрифты и измеряет каждый символ заголовка относительно обрезающих панелей. На 320 px выход в отступ не считается дефектом. Неполная загрузка страницы, шрифтов и неожиданные ответы формы дают обычную ошибку вместо `XFAIL`.

Для отдельного запуска новых сценариев с trace и скриншотами:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_booking.py::test_name_is_displayed_as_text tests/test_booking.py::test_past_date_is_rejected_after_midnight tests/test_layout.py::test_heading_is_not_clipped --runxfail --tracing on --screenshot on --output artifacts/new-regressions/diagnostic/browser --junitxml artifacts/new-regressions/diagnostic/junit.xml
```

Без `--runxfail` известные дефекты отмечаются как ожидаемые падения. С ним те же места дают обычные `FAIL`. Полный набор из 11 проверок с учётом параметров завершился **6 passed, 5 xfailed**; обычная команда запуска приведена в [README](../README.md).

### Повторение исследовательских проверок

Начать с базовых данных и изменять только значения из нужной строки. Между независимыми сценариями можно перезагружать страницу; в сценарии смены суток это нужно делать только на контрольном шаге. Для обычного заполнения подходят стандартные элементы формы, никаких изменений исходников или обхода валидации не требуется.

Для точного повторения дат и перехода суток нужны управляемые часы браузера. Локально сохранены браузерные сценарии `artifacts/exploratory-main/run.py` и `artifacts/exploratory-states/safe_probe.py`; результаты каждого — в `results.json` рядом со сценарием. Команды из корня проекта:

```powershell
.\.venv\Scripts\python.exe artifacts/exploratory-main/run.py
.\.venv\Scripts\python.exe artifacts/exploratory-states/safe_probe.py
```

Эти файлы лежат в локальном каталоге `artifacts/`, который не хранится в Git. Для повторения вручную по реальным часам выбирайте сегодняшнюю, завтрашнюю и вчерашнюю даты относительно момента проверки; сценарий полуночи требует дождаться смены дня либо задать часы в отдельном тестовом окружении.

[Журнал выполненных проверок](evidence/extended/session.json) содержит отдельную запись для каждого варианта: входные данные, ожидание, ответ формы и итог. Он хранится в проекте вместе со снимками.

## Открытые вопросы

- Разрешено ли начало встречи в текущую минуту, если её секунды уже прошли? Проверены ясные границы 11:59 и 12:01 при часах 12:00; сама текущая минута остаётся без согласованного ожидания.
- Должно ли число участников быть только целым? В требованиях это пока не закреплено, поэтому дробные значения нельзя считать успешно проверенным правилом.
- Допустима ли встреча через полночь и как указать дату её окончания? Сейчас дата одна; наблюдавшийся отказ интервалу 23:30–00:00 не отвечает на этот вопрос.
- Проверки клавиатуры и ширины окна не заменяют проверку экранным диктором, визуального фокуса, реальных мобильных устройств и других браузеров.
